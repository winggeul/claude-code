# 회사 계정으로 이전하기

개인 계정(`winggeul`)에 묶여 있는 것을 회사 소유로 옮기는 절차입니다.
저장소의 실제 코드를 읽고 확인한 내용이며, 확인하지 못한 것은 **확인 필요** 로 남겼습니다.

---

## 먼저 정할 것 두 가지

### ① GitHub — 회사 조직(Organization) 이 있습니까?

- **있으면** → 저장소를 그 조직으로 이전(Transfer)합니다
- **없으면** → 조직을 먼저 만들어야 합니다 (무료). 개인 계정끼리 넘기는 것은
  결국 또 개인 계정이라 의미가 없습니다

### ② Vercel — 유료로 갈지 무료로 갈지

Vercel 공식 문서에서 확인한 사실입니다.

> "Collaborating with other members on projects is available on the **Pro** and
> Enterprise plans. Upgrade from the Hobby plan to Pro to add team members."
>
> "Your Hobby team on Vercel can have only **one login connection** per third-party
> service."

| | A. 회사 이메일로 새 Hobby 계정 | B. Pro 팀 |
|---|---|---|
| 비용 | **무료** | **유료** (좌석당 과금 · 14일 체험 있음) |
| 여러 명이 같이 관리 | ✗ 로그인 하나만 | ✓ 초대해서 함께 |
| 이 프로젝트에 충분한가 | **충분합니다** | 과합니다 |

> **권장 — A (회사 이메일 Hobby).** 지금 이 사이트는 정적 파일 한 장 + 서버 함수 하나 +
> 숫자 두 개짜리 저장소가 전부입니다. Pro 기능이 필요한 구석이 없습니다.
> 대신 회사 공용 이메일(예: `it@회사.com`)로 만들고 그 이메일 계정을 회사가 관리해야
> 의미가 있습니다. 개인 이메일로 만들면 지금과 똑같아집니다.
>
> 여러 사람이 각자 로그인해서 배포 로그를 봐야 하는 상황이면 그때 B 로 올리면 됩니다.

## 이전 대상 (전부 4개)

| 무엇 | 지금 | 옮기는 방법 |
|---|---|---|
| GitHub 저장소 | `winggeul/claude-code` | 조직으로 Transfer |
| Vercel 프로젝트 | `daily-db-count-2mzqhq` | **옮기지 말고 새로 만듭니다** (아래 설명) |
| Vercel Blob 스토어 | `daily-db-count-2mzqhq-blob` | 새로 만들고 숫자 두 개만 다시 넣습니다 |
| VERCEL_TOKEN | 개인 발급 | 새 계정에서 새로 발급 |

### 왜 Vercel 프로젝트를 "이전" 하지 않고 "새로 만드는가"

이 사이트에는 **지켜야 할 상태가 거의 없습니다.**

- 화면은 매크로 PC 가 매번 통째로 다시 만들어 올립니다
- 데이터(`store.json`)는 매크로 PC 에 있습니다. Vercel 에는 없습니다
- Vercel 에 남아 있는 유일한 상태는 **상담사 인원 숫자 두 개** 뿐입니다

그래서 새 계정에 새 프로젝트를 만들고 한 번 배포하면 끝입니다. 이전 기능의 제약이나
실패 가능성을 떠안을 이유가 없습니다.

> **단, 주소가 바뀝니다.** `daily-db-count-2mzqhq.vercel.app` → 새 주소.
> 이 링크를 받아 본 사람 전원에게 다시 공지해야 합니다.
> (커스텀 도메인을 쓰고 계셨다면 주소를 유지할 수 있습니다 — **확인 필요**)

그리고 이 파일을 **PC 밖으로** 복사하세요 (사내 공유 드라이브, 메일 첨부, USB 무엇이든).

건수만 들어 있어 개인정보가 없으므로 어디에 두어도 괜찮습니다.

### 1단계 — GitHub 저장소 이전

회사 조직이 없으면 먼저 만듭니다: <https://github.com/organizations/plan> → Free 선택

그다음:

1. <https://github.com/winggeul/claude-code/settings> 접속
2. 맨 아래 **Danger Zone** → **Transfer ownership**
3. 새 소유자에 회사 조직 이름 입력 → 저장소 이름 입력해 확인

**이전 후 브랜치를 정리하는 것을 권합니다.** 지금 운영 브랜치 이름이
`claude/crm-data-connection-2nbows` 로 길고 알아보기 어렵습니다. 이 기회에 `main` 으로
옮기면 이후 관리가 쉽습니다. (하지만 브랜치를 바꾸면 2단계 주소도 그에 맞춰 고쳐야 합니다)

> GitHub 는 이전 후 옛 주소에서 새 주소로 리다이렉트를 걸어줍니다. 다만 코드에 박힌
> 주소는 **직접 고치는 것이 맞습니다.** 리다이렉트에 기대면 언젠가 조용히 끊깁니다.

계정을 옮기면 아래 **4곳**이 안 맞게 됩니다. 저장소 전체를 검색해 확인한 목록입니다.

| 파일 | 줄 | 무엇 |
|---|---|---|
| `tools/crm4_daily.ps1` | 72 | `$TemplateUrl` — **이게 안 맞으면 화면 자동 갱신이 조용히 멈춥니다** |
| `tools/점검.ps1` | 25 | `$Site` — 점검 스크립트가 보는 사이트 주소 |
| `tools/점검.ps1` | 26 | `$TemplateUrl` |
| `tools/SETUP.md` | 273 | 설치 안내서 본문의 주소 |

`docs/인수인계.md` 에도 주소가 15곳 나옵니다. 이전이 끝난 뒤 한꺼번에 고치면 됩니다.

바꿀 모양은 이렇습니다.

```
# 지금
https://raw.githubusercontent.com/winggeul/claude-code/refs/heads/claude/crm-data-connection-2nbows/dashboard/index.html

# 바꾼 뒤 (조직명과 브랜치명은 실제 것으로)
https://raw.githubusercontent.com/회사조직명/저장소명/refs/heads/main/dashboard/index.html
```

고친 뒤 커밋해서 올립니다.

> **주의 — 저장소를 Private 으로 만들면 이 방식이 깨집니다.**
> 매크로 PC 가 `raw.githubusercontent.com` 에서 로그인 없이 화면 틀을 받아가는 구조입니다.
> Private 으로 바꾸시려면 다른 방법(토큰을 붙이거나, 화면 갱신을 수동으로)이 필요합니다.
> 지금 저장소에는 데이터가 없고 코드와 빈 화면 틀만 있어서 Public 이어도 문제는 없습니다.

### 3단계 — Vercel 새 계정 + 새 프로젝트

1. 회사 이메일로 <https://vercel.com> 가입 (위에서 A 를 골랐을 경우)
2. 매크로 PC 에서 그 계정으로 로그인하고 새 프로젝트로 한 번 배포합니다

```powershell
cd C:\CRM자동화\site
npx.cmd vercel login
```

```powershell
# 옛 프로젝트와의 연결을 끊습니다
Remove-Item .\.vercel -Recurse -Force -ErrorAction SilentlyContinue
```

```powershell
# 새 프로젝트로 연결합니다. 이름은 알아보기 쉬운 것으로
npx.cmd vercel link --yes --project db-dashboard
```

```powershell
npx.cmd vercel deploy . --prod
```

끝에 나오는 **Aliased 주소**가 앞으로 쓸 주소입니다. 적어 두세요.

> `npx` 가 아니라 **`npx.cmd`** 입니다. 그냥 `npx` 로 치면 PowerShell 실행 정책에 막힙니다.
> Pro 팀으로 가신 경우에는 명령마다 `--scope 팀슬러그` 를 붙여야 할 수 있습니다.

---

### 4단계 — Blob 스토어 (상담사 인원 저장소)

새 계정에 새로 만드는 것이 간단합니다. 저장된 것이 숫자 두 개뿐이라 옮길 게 없습니다.

1. Vercel 대시보드 → 새 프로젝트 → **Storage** 탭 → **Create Database** → **Blob**
2. `Store Name`, `Region` 은 기본값 그대로
3. `Access` 는 **Private** 그대로
4. **`Add a read-write token env var to this connection` 을 반드시 체크**
5. 만든 뒤 **Connect Project** 로 새 프로젝트에 연결

체크를 빠뜨리면 `BLOB_READ_WRITE_TOKEN` 이 안 들어가서 인원 저장이 안 됩니다.

> 스토어 화면의 주황색 **`Revoke Token` 은 누르지 마세요.**
>
> 굳이 기존 스토어를 그대로 옮기고 싶다면 스토어 Settings 에 **Transfer Store** 가 있습니다
> ("Transfer this store to another team without downtime"). 다만 이 프로젝트에서는
> 새로 만드는 편이 단순합니다.

---

### 5단계 — 토큰 교체

1. 새 계정에서 <https://vercel.com/account/tokens> → 토큰 발급
2. 매크로 PC 에 **관리자 권한 PowerShell** 로 등록

```powershell
[Environment]::SetEnvironmentVariable("VERCEL_TOKEN", "새로발급받은토큰", "Machine")
```

3. PowerShell 을 **새로 열고** 확인

```powershell
$env:VERCEL_TOKEN.Length
```

숫자가 나오면 등록된 것입니다. **토큰 값 자체는 채팅이나 문서에 붙여넣지 마세요.**

### 6단계 — 전체 동작 확인

```powershell
cd C:\CRM자동화
powershell -ExecutionPolicy Bypass -File .\crm4_daily.ps1 -SkipCollect
```

끝에 `배포 완료` 와 새 주소가 나오면 성공입니다. 그다음 확인:

- [ ] 새 주소로 화면이 뜨는가
- [ ] `새주소/api/headcount` 가 `{"시흥":5,"천안":11,"updated":"..."}` 를 주는가
      (`"fallback": true` 가 보이면 4단계의 토큰 체크를 빠뜨린 것)
- [ ] 화면에서 인원을 눌러 바꿔 보고, 휴대폰에서 같은 주소를 열어 같은 값이 보이는가
- [ ] 표에 `날짜 · 시흥 · 천안 · 합계 · 인당` 이 다 나오는가

한 번에 9개 항목을 보려면:

```powershell
powershell -ExecutionPolicy Bypass -File .\점검.ps1
```

(2단계에서 `점검.ps1` 의 주소를 고쳐 두었어야 정확히 나옵니다)

## 이전해도 여전히 남는 위험

계정을 옮겨도 **이건 안 풀립니다.**

**매크로 PC 한 대에 수집이 전부 묶여 있습니다.** 그 PC 가 꺼지거나 화면이 잠기면 그날
데이터가 안 들어오고, **끊긴 날은 나중에 메울 수 없습니다** (지난 날짜를 다시 뽑으면
그 사이 상담사가 수정한 값이 반영돼 다른 날과 기준이 어긋나기 때문입니다).

계정 이전과 별개로, 예비 PC 세팅과 `store.json` 자동 백업을 따로 잡으셔야 합니다.

- 회사 GitHub 조직이 있는지 / 만들 권한이 있는지
- 커스텀 도메인을 쓰고 있는지 (쓰고 있다면 주소를 유지할 수 있습니다)
- Vercel 을 유료(Pro)로 갈지 무료(Hobby)로 갈지 — 회사 정책
- 회사 공용 이메일 계정을 쓸 수 있는지
