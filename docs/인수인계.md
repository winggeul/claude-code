# 일자별 DB 수량 대시보드 — 업무 인수인계서

작성일 2026-09-02 · 저장소의 실제 코드와 설정 파일을 읽고 확인한 내용만 적었습니다.
확인하지 못한 것은 **확인 필요** 로 남겼습니다.

---

## 1. 개요

CRM4enterprise 의 `통합고객목록` 에서 매일 전날 등록 건을 자동으로 받아, 유입경로별·지점별
건수를 세어 웹 대시보드로 보여주는 시스템입니다. 시흥·천안 두 지점으로 나눠 집계하고
상담사 1인당 건수까지 계산합니다.

고객 이름과 전화번호는 집계 단계에서 버려지고, 이후로는 `{날짜, 유입경로, 지점, 건수}` 만
흐릅니다. 웹에 올라가는 파일에는 개인정보가 들어 있지 않습니다.

## 2. 실행 환경

| | |
|---|---|
| 웹 호스팅 | **Vercel** (프로젝트명 `daily-db-count-2mzqhq`) |
| 리전 | `iad1` (미국 워싱턴 D.C.) — 응답 헤더 `x-vercel-id: iad1::...` 로 확인 |
| 요금제 | Hobby (무료) — 버셀 화면 캡처에서 확인 |
| 데이터 수집 | **사내 매크로 PC (Windows)** 에서 실행 |
| 매크로 PC 작업 폴더 | `C:\CRM자동화` — 실행 로그의 프롬프트 `PS C:\CRM자동화>` 로 확인 |
| 자동 실행 여부 | **자동.** Windows 작업 스케줄러 2개 |

**중요 — 서버가 두 군데로 나뉘어 있습니다.**

- 화면(웹)은 Vercel 이 24시간 띄웁니다. 매크로 PC 가 꺼져 있어도 화면은 계속 보입니다.
- 데이터 수집·집계·배포는 **매크로 PC 에서만** 돕니다. 이 PC 가 꺼지거나 화면이 잠기면
  그날 데이터가 안 들어옵니다.

## 3. 실행 주기

작업 스케줄러에 등록된 작업 2개입니다. 등록 명령은 `tools/SETUP.md` 6번 항목에 있습니다.

| 작업 이름 | 주기 | 하는 일 |
|---|---|---|
| `CRM4 일일수집` | 매일 06:00 시작, 2시간 간격으로 12시간 재시도 (06·08·10·12·14·16·18시) | CRM4 에서 **어제 하루치** CSV 를 받아 집계하고 배포 |
| `CRM4 화면갱신` | 00:00 시작, **10분 간격**으로 24시간 | 화면 틀만 확인. 바뀌었을 때만 다시 만들어 배포. CRM4 는 건드리지 않음 |

**스케줄 설정 위치** — 매크로 PC 의 작업 스케줄러(taskschd.msc). 저장소에는 등록용 PowerShell
명령이 `tools/SETUP.md` 에 문서로만 들어 있고, cron 파일이나 GitHub Actions 워크플로는
**없습니다** (`.github/` 폴더 없음을 확인).

**수집 범위 규칙 (코드로 확인)** — `crm4_daily.ps1` 의 기본값이
`[datetime]$End = (Get-Date).Date.AddDays(-1)` 입니다. 항상 **어제 하루만** 받습니다.
빠진 날을 저절로 메우지 않습니다. 지난 날짜를 다시 뽑으면 그 사이 상담사가 수정한 값이
반영돼 다른 날과 기준이 어긋나기 때문입니다. 굳이 받으려면 `-Backfill` 을 명시해야 합니다.

일요일은 건너뜁니다. 이미 받아 둔 날이면 CRM4 를 건드리지 않고 몇 초 만에 끝납니다.

## 6. 입력과 출력

### 흐름

```
CRM4enterprise 통합고객목록 화면
   │  crm4_collect.ps1 이 화면을 조작해 CSV 내보내기
   ▼
C:\CRM자동화\raw\customers_YYYY-MM-DD.csv     (euc-kr 인코딩)
   │  aggregate.mjs 가 세고, 이름·전화번호를 버림
   ▼
C:\CRM자동화\store.json                        (누적 집계본)
   │  template.html 의 데이터 자리에 끼워 넣음
   ▼
C:\CRM자동화\site\index.html
   │  npx vercel deploy
   ▼
https://daily-db-count-2mzqhq.vercel.app
```

원본 CSV 는 집계에 성공하면 **삭제**됩니다 (`--delete` 옵션). `-KeepRaw` 를 주면 남습니다.

### 입력 — CSV 에서 읽는 것

`aggregate.mjs` 가 헤더 이름으로 열을 찾고, 헤더가 없으면 값의 생김새로 찾습니다.

- **등록일** — 날짜
- **유입경로** — 예: `유튜브-PPL(5504)♨`
- **담당자** — 이름으로 시흥/천안을 가름. 열 위치가 내보내기마다 달라서
  `roster.mjs` 의 명단과 맞춰 찾습니다

### 집계 규칙 (코드로 확인)

- `협력점해피콜` 로 시작하는 유입경로는 **제외**합니다 (신규 인입이 아니라 기존 고객 확인 전화)
- 유입경로가 비었거나 전화번호가 들어간 건은 `미지정` 으로 묶습니다
  (공개 화면에 고객 번호가 실리지 않게 하려는 처리입니다)
- 담당자가 명단에 없으면 시흥 5 : 천안 11 비율로 번갈아 배분합니다.
  그래서 **시흥 + 천안 = 합계** 가 항상 맞습니다

### 출력 — `store.json` 형식

```json
{
  "generated": "2026-08-31T21:00:36",
  "excluded": ["협력점해피콜"],
  "headcount": { "시흥": 5, "천안": 11 },
  "rows": [
    { "date": "2026-07-01", "channel": "구글-키워드(4869)", "branch": "시흥", "count": 4 }
  ]
}
```

하루 × 유입경로 × 지점 한 줄입니다. 개인정보 없음.

### 화면에 보여주는 것

KPI 카드(최신일·지점별·주간·월간·영업일 평균·인당 일평균·최다 유입경로), 전체 추이
꺾은선, 유입경로별 구성 누적 막대, 채널별 인입 수량 표.
일자별 / 주차별 / 월별로 전환됩니다. 토·일·공휴일은 평균 계산에서 제외합니다.

## 8. 장애 대응

### 먼저 한 줄로 상태 보기

브라우저에서 이 주소를 엽니다.

```
https://daily-db-count-2mzqhq.vercel.app/api/headcount
```

- `{"시흥":5,"천안":11,"updated":"..."}` → 서버·저장소 정상
- `"fallback": true` 가 보이면 → 인원 저장소를 못 읽는 중 (아래 C 참고)
- 아예 안 열리면 → 배포 자체에 문제

### A. 사이트가 아예 안 뜬다

1. Vercel 대시보드 → 프로젝트 `daily-db-count-2mzqhq` → Deployments 에서 마지막 배포 상태 확인
2. 실패했으면 로그를 보고, 직전 성공 배포에서 **Redeploy**
3. 매크로 PC 에서 다시 올려도 됩니다 (아래 재배포 명령)

### B. 화면은 뜨는데 데이터가 안 갱신된다

화면 위쪽 부제에 `마지막 갱신` 날짜가 찍힙니다. 어제 날짜가 아니면 수집이 안 돈 겁니다.

**매크로 PC 에서 순서대로 확인합니다.**

```powershell
# 1) 작업이 살아 있는지, 마지막 실행이 성공(0)인지
Get-ScheduledTaskInfo -TaskName "CRM4 일일수집" | Select-Object LastRunTime, LastTaskResult, NextRunTime
Get-ScheduledTaskInfo -TaskName "CRM4 화면갱신" | Select-Object LastRunTime, LastTaskResult, NextRunTime

# 2) 오늘 로그 보기 (가장 최근 파일)
Get-ChildItem C:\CRM자동화\logs\*.txt | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | Get-Content

# 3) 한 번에 9개 항목 점검 (확인만 함. 아무것도 바꾸지 않음)
cd C:\CRM자동화
powershell -ExecutionPolicy Bypass -File .\점검.ps1
```

**자주 있는 원인**

| 증상 | 원인 | 조치 |
|---|---|---|
| 로그에 "통합고객목록 창을 열어주세요" | CRM4 가 꺼져 있거나 창이 닫힘 | CRM4 실행 후 `고객관리 > 통합고객목록` 창을 열어 둡니다 |
| 로그가 아예 없음 | PC 가 꺼졌거나 화면이 잠김 | 전원 설정에서 화면 끄기·절전을 `안 함` 으로. 화면 보호기 잠금 해제 |
| "이미 받아 두었습니다" | 정상. 그날 것은 이미 들어옴 | 조치 불필요 |
| "지난 날짜라 받지 않았습니다" | 하루 이상 밀림 | 아래 과거분 받기 참고 |
| "npx 를 찾지 못했습니다" | Node.js 문제 | Node.js 재설치 후 PowerShell 새로 열기 |

### C. 인원 숫자가 저장이 안 된다 / 사람마다 다르게 보인다

1. `https://daily-db-count-2mzqhq.vercel.app/api/headcount` 를 엽니다
2. `"fallback": true` 가 있으면 → Vercel 프로젝트 → Settings → Environment Variables 에서
   **`BLOB_READ_WRITE_TOKEN` 이 있는지** 확인
3. 없으면 → Storage → Blob 스토어 → Projects 탭 → 프로젝트 연결을 지웠다가,
   `Add a read-write token env var to this connection` 을 **체크**하고 다시 연결
4. 연결 후 매크로 PC 에서 재배포 (아래 명령)

> Blob 스토어 화면의 주황색 **`Revoke Token` 은 누르면 안 됩니다.** 인원 저장이 멈춥니다.

### 재실행 · 재배포 명령 (매크로 PC, 그대로 복사)

```powershell
cd C:\CRM자동화
```

```powershell
# 전체 (수집 → 집계 → 배포). 어제치를 받습니다

```

```powershell

```

```powershell
# 배포 없이 결과 파일만 만들기 (site\index.html 확인용)

```

## 9. 수정이 필요한 상황

값이 바뀌면 코드를 고쳐야 하는 지점입니다. 모두 `dashboard/index.html` 또는 `tools/roster.mjs`
안의 상수이고, 고쳐서 GitHub 에 올리면 **10분 안에 자동 반영**됩니다
(매크로 PC 의 `화면갱신` 작업이 GitHub raw 에서 `dashboard/index.html` 을 받아갑니다).

| 무엇이 바뀌면 | 어디를 고치나 | 비고 |
|---|---|---|
| 상담사가 입사·퇴사·지점 이동 | `tools/roster.mjs` 의 시흥/천안 명단 | 안 고쳐도 합계는 맞지만 그 사람 건이 엉뚱한 지점으로 갑니다 |
| 해가 바뀜 (2027년 등) | `dashboard/index.html` 의 `HOLIDAYS` 목록 | 공휴일이 안 적혀 있으면 평일로 잡혀 평균이 낮아집니다. 화면 위에 경고가 뜹니다 |
| 지난달 총 인원이 달랐던 경우 | `dashboard/index.html` 의 `HEADCOUNT` (현재 `{"2026-07": 15}` 만 있음) | 이번 달부터는 지점 인원 합을 자동으로 씁니다 |
| 지점별 인원 기본값 | `dashboard/index.html` 의 `HEAD_BASE`, `dashboard/api/headcount.js` 의 `DEFAULT` | **평소 인원 변경은 코드 수정 없이 화면에서 숫자를 눌러 바꾸면 됩니다** |
| 유입경로 이름 오타 | `dashboard/index.html` 의 `TYPO` 표 | |
| 집계에서 뺄 유입경로 추가 | `tools/aggregate.mjs` 와 `tools/backfill_xlsx.mjs` 의 `EXCLUDE` | **두 곳 다** 고쳐야 과거분과 기준이 안 어긋납니다 |
| 색으로 구분할 채널 수 | `dashboard/index.html` 의 `TOP_N` (현재 11) | |
| Vercel 프로젝트를 새로 만듦 | `tools/crm4_daily.ps1` 의 배포 대상, `점검.ps1` 의 `$Site` 주소 | |
| GitHub 브랜치명 변경 | `tools/crm4_daily.ps1` 의 `$TemplateUrl` | 이 주소가 안 맞으면 화면 자동 갱신이 멈춥니다 |

## ⚠ 지금 담당자 개인/PC 에 묶여 있는 부분

인수인계에서 **가장 먼저 풀어야 할 것들**입니다. 담당자가 없으면 멈춥니다.

### 1. 매크로 PC 한 대에 전부 묶여 있습니다 — 가장 큰 위험

수집·집계·배포가 **그 PC 한 대에서만** 돕니다. 대체 장비도, 다른 PC 로 넘길 절차도
없습니다. PC 가 고장 나거나 회수되면 그날부터 데이터가 끊깁니다.

그리고 **끊긴 날은 나중에 메울 수 없습니다.** 지난 날짜를 다시 뽑으면 그 사이 상담사가
수정한 값이 반영돼 다른 날과 기준이 어긋나기 때문입니다. 설계상 그렇게 막아 놨습니다.

> **필요한 조치** — 예비 PC 에 `tools/SETUP.md` 대로 세팅해 두거나, 최소한 세팅 절차를
> 인수자가 직접 한 번 해보게 할 것.

### 2. `store.json` 이 그 PC 에만 있고 백업이 없습니다

7월 1일부터 쌓인 모든 숫자가 이 파일 하나에 들어 있습니다. `.gitignore` 에 `dist/` 가
있어 저장소에는 한 번도 올라간 적이 없습니다. 파일이 날아가면 **복구 불가**입니다.

> **필요한 조치** — 네트워크 드라이브나 클라우드로 매일 자동 복사되게 할 것.
> 개인정보가 없는 파일이라 어디에 두어도 무방합니다.

### 3. Vercel 계정이 개인 계정(`winggeul`)입니다

무료 Hobby 요금제이고, 사이트·서버 함수·인원 저장소가 전부 이 계정 아래 있습니다.
계정을 잃거나 해지하면 사이트가 사라집니다.

> **필요한 조치** — 팀 계정으로 이전(Transfer)하거나, 최소한 계정 정보를 회사가
> 보관할 것. Blob 스토어도 함께 이전해야 합니다 (버셀 Settings 에 Transfer Store 있음).

### 4. `VERCEL_TOKEN` 이 담당자가 발급한 개인 토큰입니다

매크로 PC 의 시스템 환경변수에 들어 있습니다. 담당자 계정이 정리되면 토큰도 무효가 되고
배포가 멈춥니다. 로그에는 `VERCEL_TOKEN 이 없어 배포를 건너뜁니다` 라고 찍힙니다.

> **필요한 조치** — 인수자 계정으로 새 토큰을 발급해 환경변수를 교체할 것.

### 5. GitHub 저장소가 개인 계정이고, 브랜치 주소가 코드에 박혀 있습니다

`crm4_daily.ps1` 의 `$TemplateUrl` 이
`raw.githubusercontent.com/winggeul/claude-code/refs/heads/claude/crm-data-connection-2nbows/dashboard/index.html`
로 고정돼 있습니다. 저장소를 옮기거나 브랜치 이름을 바꾸면 **화면 자동 갱신이 조용히
멈춥니다** (수집은 계속 되므로 알아채기 어렵습니다).

> **필요한 조치** — 저장소를 회사 조직으로 옮길 때 이 주소도 같이 고칠 것.

### 6. CRM4 화면 구조에 의존합니다

수집기가 CRM4enterprise 창의 컨트롤 위치를 찾아 클릭하는 방식입니다. CRM4 가 업데이트돼
화면이 바뀌면 수집이 실패할 수 있습니다. 이때는 `crm4_collect.ps1 -Diagnose` 로 어디서
막히는지 확인하고 코드를 고쳐야 합니다 — **개발자 손이 필요한 작업**입니다.
