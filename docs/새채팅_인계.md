# 새 채팅방에 붙여넣을 인계 내용

계정 이전을 마친 뒤, 다른 채팅방에서 이 프로젝트를 이어서 다루려면 아래를 붙여넣으세요.
**`{{ }}` 부분은 이전을 마친 뒤 실제 값으로 바꿔야 합니다.**

---

## 1. 채팅 첫 메시지로 붙여넣을 것

아래 코드블록 안을 통째로 복사해서 새 채팅방 첫 메시지로 보내면 됩니다.

```
CRM 유입경로 대시보드를 이어서 관리하려고 해. 배경부터 알려줄게.

[무엇]
CRM4enterprise 의 통합고객목록에서 매일 전날 등록 건을 자동으로 받아,
유입경로별·지점별(시흥/천안) 건수를 세어 웹 대시보드로 보여주는 시스템이야.
고객 이름과 전화번호는 집계 단계에서 버려서 웹에는 건수만 올라가.

[코드]
저장소  https://github.com/woori-marketing/crm-db-dashboard
브랜치  main
핵심 파일
  dashboard/index.html      대시보드 화면 전부 (프레임워크 없는 순수 HTML/CSS/JS)
  dashboard/api/headcount.js 상담사 인원 저장·조회 서버 함수 (Vercel)
  tools/crm4_daily.ps1      매일 도는 전체 작업. 스케줄러가 실행
  tools/crm4_collect.ps1    CRM4 화면을 조작해 CSV 받아오기
  tools/aggregate.mjs       CSV 를 세어 store.json 과 화면 HTML 생성
  tools/roster.mjs          담당자 이름 → 시흥/천안 명단
  tools/SETUP.md            매크로 PC 설치 안내서
  docs/인수인계.md          운영 인수인계서 (이걸 먼저 읽으면 빠름)
  docs/계정이전.md          계정 이전 절차서

[운영]
웹      {{새주소}}  (로그인 없음. 주소를 아는 사람은 누구나 볼 수 있음)
호스팅  Vercel · 프로젝트 {{프로젝트명}} · 계정 {{회사계정}}
수집    사내 매크로 PC C:\CRM자동화 에서 Windows 작업 스케줄러로 자동 실행
        - CRM4 일일수집   매일 06:00 (실패 시 2시간 간격 18시까지 재시도)
        - CRM4 화면갱신   10분마다 (GitHub 에서 화면 틀만 받아 바뀌었으면 재배포)

[꼭 알아야 할 규칙]
1. 수집은 항상 "어제 하루만" 받아. 빠진 날을 저절로 메우지 않아.
   지난 날짜를 다시 뽑으면 그 사이 상담사가 수정한 값이 반영돼서
   다른 날과 기준이 어긋나거든. 그래서 끊긴 날은 영영 못 채워.
2. store.json 이 유일한 누적본이고 매크로 PC 에만 있어. 저장소에 없어(.gitignore).
   이게 날아가면 복구 불가야.
3. dashboard/index.html 을 고쳐서 GitHub 에 올리면 10분 안에 화면에 자동 반영돼.
   매크로 PC 에 갈 필요 없어.
4. 협력점해피콜은 집계에서 제외해. 신규 인입이 아니라 기존 고객 확인 전화라서.
5. 담당자 명단에 없는 사람의 건은 시흥 5 : 천안 11 로 나눠 담아.
   그래서 시흥 + 천안 = 합계가 항상 맞아.
6. 상담사 인원은 화면에서 숫자를 눌러 바꾸면 모든 PC 에 반영돼 (Vercel Blob 에 저장).
   코드 수정 아니야.

[앞으로 할 일]
- 예비 PC 세팅 (지금 매크로 PC 한 대에 전부 묶여 있음)
- store.json 자동 백업

앞으로 화면을 고쳐 달라고 하면 완성된 HTML 파일도 같이 줘.
```

## 2. 같이 첨부할 파일

새 채팅방에 아래 파일을 올려 주면 훨씬 빨리 파악합니다.

| 파일 | 어디서 | 왜 |
|---|---|---|
| `docs/인수인계.md` | 저장소 | 10개 항목 운영 문서. 이거 하나면 대부분 답이 나옴 |
| `docs/계정이전.md` | 저장소 | 이전 절차와 남은 위험 |
| `tools/SETUP.md` | 저장소 | 매크로 PC 를 새로 세팅할 때 |
| `store.json` | 매크로 PC `C:\CRM자동화\` | 숫자 분석을 시킬 때 필요. 개인정보 없음 |
| 최근 로그 | 매크로 PC `C:\CRM자동화\logs\` | 문제가 생겼을 때만 |

저장소 주소만 알려줘도 코드는 읽을 수 있지만, `store.json` 은 저장소에 없으므로
데이터를 봐야 하는 일이면 직접 올려야 합니다.

## 3. 절대 채팅에 붙여넣지 말 것

| | 대신 |
|---|---|
| `VERCEL_TOKEN` 값 | "환경변수에 등록돼 있다" 고만 |
| `BLOB_READ_WRITE_TOKEN` 값 | 마찬가지 |
| CRM4 / GitHub / Vercel 비밀번호 | 별도 경로로 전달 |
| 고객 이름·전화번호가 든 원본 CSV | `store.json` 을 쓰세요. 건수만 들어 있습니다 |

원본 CSV(`C:\CRM자동화\raw\`)에는 고객 이름과 전화번호가 들어 있습니다.
집계 후 자동 삭제되지만, 남아 있는 것을 발견해도 채팅에 올리면 안 됩니다.

## 4. 이전을 마치고 채워야 할 값

위 1번 붙여넣기의 `{{ }}` 를 채우는 데 필요한 것입니다.

| 자리 | 어디서 확인 |
|---|---|
| `{{새주소}}` | 배포 로그 끝의 **Aliased** 주소 |
| `{{프로젝트명}}` | Vercel 대시보드 |
| `{{회사계정}}` | 새로 만든 Vercel 계정 |
