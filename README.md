# CRM4enterprise 데이터 자동 수집

원투원솔루션(OtOSolution)의 `CRM4enterprise` 에서 고객·상담 데이터를 자동으로
뽑아내기 위한 작업 저장소.

## 조사 결과

설치된 PC 에서 확인한 사실:

| 항목 | 값 |
|---|---|
| 실행 파일 | `C:\Program Files (x86)\OtOSolution\CRM4enterprise\CRM4enterprise.exe` |
| 로컬 DB 파일 | **없음** (`.mdb` / `.sdf` / `.sqlite` 전부 미발견) |
| 로컬 설정 파일 | `CRM4enterprise.exe.config` 한 개뿐 |
| 원격 연결 | `211.253.10.23:22443`, `211.253.10.48:63443` (ESTABLISHED) |
| 공개 API | 없음 (벤더 문서·다운로드 페이지 전수 확인) |

`211.253.10.x` 대역은 벤더 웹서버(`otosolution.com` = `211.253.26.37`)와 같은
사업자 할당 대역이다. 즉 **데이터는 PC 가 아니라 벤더 서버에 있고**, 클라이언트는
비표준 포트의 자체 프로토콜로 그걸 받아 화면에만 뿌린다.

따라서 파일을 읽거나 DB 에 붙는 방식은 불가능하다. 남는 경로는 두 개다.

## 경로 A — 벤더 API (정공법, 진행 권장)

엔터프라이즈 계약 건이므로 원투원솔루션에 DB 스키마 또는 연동 API 제공을 요청한다.
승인되면 그 규격에 맞춰 수집기를 새로 작성한다. 가장 안정적이지만 벤더 응답에 의존한다.

## 경로 B — 화면 자동화 → **실패, 폐기**

`tools/crm4_dump.ps1` 로 실제 화면(통합고객목록)을 조사한 결과, 두 가지 이유로 불가능.

**1. UI Automation 이 표를 못 읽는다.** 잡힌 컨트롤 42 개가 전부 `ControlType.Pane`,
클래스는 전부 `WindowsForms10.*`. **Grid 패턴 0 개.** 목록은 `id=918888` Pane 안에
직접 그려지는 커스텀 컨트롤이라 접근성 정보를 일절 노출하지 않는다. 화면에 보여도
프로그램이 읽을 수 있는 텍스트가 아니다.

**2. 규모가 화면 긁기로 감당이 안 된다.** 화면 상단 표시:

```
전체고객 : 742678명    담당고객 : 0명    조회고객 : 30명
```

74 만 건이다. 한 번에 30 건씩 보이는 화면을 넘겨가며 긁는 방식은 성립하지 않는다.

## 경로 C — 관리자 도구 (다음 조사 대상)

화면에서 확인된 로그인 계정이 `mj321_admin`, 즉 **관리자 권한**이다. 벤더가 배포하는
관리자용 도구와 웹 포털이 따로 있으므로 여기에 일괄 추출 기능이 있을 가능성이 높다.

| 대상 | 위치 |
|---|---|
| 관리자 웹 | `https://otosolution.com/admin/` |
| CRMadmin | `http://otosolution.com/solution/CRMadmin/CRMadmin_Setup.exe` |
| CRMloader | `http://otosolution.com/solution/CRMloader/CRMloader_Setup.exe` |

`CustomerUpload.aspx` 로 고객정보 **업로드**가 제공되는 구조이므로 반대 방향인
다운로드/내보내기도 존재할 개연성이 있다. 이름상 `CRMloader` 가 일괄 처리 도구로 보인다.

## 대상 화면 확정 — 통합고객목록 (IntegrateCustomerList)

메뉴: `고객관리(C)` → `통합고객목록(IntegrateCustomerList)`

창 구성: `고객조건` / `고객제외조건` / `상담조건` / `상담제외조건` / `목록` / `처리` 탭 + `검색` 버튼

`목록` 탭 컬럼: 등록일 · 회사명 · 이름 · 전화번호 · 유입경로 · 인입일시

### 규모 문제는 해결 가능

`고객조건` 탭에 **등록일 범위 필터**가 있다. 74 만 건을 한 번에 다룰 필요가 없다는 뜻이다.

- 신규 수집: 하루 단위로 돌리면 회당 수십 건 (실측: 2026-08-21 하루 = 30 건)
- 과거 백필: 등록일을 하루씩 밀며 반복

즉 **날짜로 잘라서 반복**하면 전량 확보가 가능하다. 남은 문제는 "잘라낸 결과를 어떻게
프로그램이 읽어내느냐" 하나뿐이다.

### 다음 검증 — 화면을 읽지 않고 데이터를 빼는 두 경로

UIA 로 격자를 못 읽는 건 확정. 대신 격자를 읽지 않아도 되는 방법 두 가지를 확인한다.

1. **`처리` 탭** — 일괄 작업 탭. 내보내기/저장 기능이 있으면 그 버튼을 자동으로
   누르는 방식으로 끝난다. 사람이 누르는 게 아니라 스케줄러가 누르므로 자동화 요건에 부합.
2. **전체선택 + 클립보드 복사** — `목록` 탭 좌하단 `전체선택` 체크 후 Ctrl+C 가
   먹으면 클립보드에 탭 구분 텍스트가 실린다. 클립보드는 UIA 와 무관하게 읽을 수 있으므로
   격자 문제를 완전히 우회한다.

둘 중 하나만 되면 전체 자동화가 성립한다.


## 확보한 추출 경로 (검증 완료)

`통합고객목록` → `처리` 탭에 **`Excel` 버튼**이 있다. 그리고 `목록` 탭에서 전체선택 후
Ctrl+C 로 클립보드 복사도 동작한다. 격자를 읽지 못하는 문제는 두 경로 모두 우회한다.

| 경로 | 장점 | 위험 |
|---|---|---|
| `처리` 탭 Excel 버튼 | 전체 컬럼이 원본 그대로 나옴 | 저장 대화상자 처리 필요 |
| 전체선택 + Ctrl+C | 대화상자 없음, 단순 | 화면에 보이는 컬럼만 나올 수 있음 |

Excel 버튼을 주 경로로 하고 클립보드를 대체 경로로 둔다.

### 왜 Win32 백엔드인가

UIA 로는 모든 컨트롤이 밋밋한 `Pane` 으로만 보였으나, 클래스 이름이
`WindowsForms10.EDIT` / `.BUTTON` / `.COMBOBOX` 인 것에서 보이듯 실체는 진짜 Win32
자식 윈도우다. 따라서 **win32 백엔드로는 핸들을 직접 잡아 값을 넣고 누를 수 있다.**
읽지 못하는 것은 커스텀 격자 하나뿐이고 그건 위 두 경로가 대신한다.

`tools/crm4_probe.py` 가 그 핸들과 컨트롤 ID 를 수집한다.

### 수집기 동작 설계

```
매일 새벽 실행
  → 통합고객목록 열기
  → 고객조건 탭에서 등록일 = 대상일 ~ 대상일 설정
  → 검색
  → 처리 탭 → Excel  (실패 시: 목록 탭 → 전체선택 → Ctrl+C)
  → 결과를 누적 저장
과거분은 등록일을 하루씩 밀며 같은 절차 반복
```
